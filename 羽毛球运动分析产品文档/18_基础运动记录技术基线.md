# 基础运动记录技术基线

## 1. 文档状态

- 版本：0.1
- 日期：2026-08-12
- 对应任务：S4-001 至 S4-006
- 当前结论：阶段 4 Simulator 代码基线完成，真机门禁未通过

本文落实 Apple Watch 羽毛球基础运动记录，不授权击球检测、杀球分类或杀球测速。任何模拟器指标都不得作为用户运动事实、研究样本或 HealthKit 成功记录。

## 2. 平台实现依据

正式 Watch 端采用 Apple 官方运动链路：

- 使用 `HKWorkoutConfiguration`，运动类型固定为 `.badminton`；
- 使用 `HKWorkoutSession` 管理开始、暂停、继续、停止和平台错误；
- 使用 `HKLiveWorkoutBuilder` 与 `HKLiveWorkoutDataSource` 汇总心率和能量；
- 申请写入 workout，读取心率、活动能量和基础能量所需权限；
- Watch target 声明 HealthKit entitlement、用途说明和 `workout-processing` 后台模式；
- 结束时先停止 session 并等待 `.stopped`，再 `endCollection`、`finishWorkout`，最后释放会话；
- `finishWorkout` 返回 workout 为空且 error 为空时按 Apple 文档视为保存成功，但本地没有可记录的 HealthKit UUID。

主要依据：

- [Running workout sessions](https://developer.apple.com/documentation/healthkit/running-workout-sessions)
- [Authorizing access to health data](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)
- [Workouts and activity rings](https://developer.apple.com/documentation/healthkit/workouts-and-activity-rings)
- [Badminton workout activity type](https://developer.apple.com/documentation/healthkit/hkworkoutactivitytype/badminton)
- [Finishing a live workout](https://developer.apple.com/documentation/healthkit/hkworkoutbuilder/finishworkout%28completion%3A%29)
- [Recovering an active workout after relaunch](https://developer.apple.com/documentation/watchkit/wkapplicationdelegate/handleactiveworkoutrecovery%28%29)

## 3. 模块边界

### 3.1 共享核心

- `BadmintonWorkoutRecord`：算法无关的版本化运动事实；
- `WorkoutPlatformSession`：HealthKit 与 Simulator 的可替换平台边界；
- `BadmintonWorkoutSessionCoordinator`：授权、状态转换、指标接收和失败处理；
- `BadmintonWorkoutFileStore`：每场运动一个目录、原子 JSON 检查点与异常恢复。

共享核心不依赖 SwiftUI 或 HealthKit，状态机和存储可以在 macOS 单元测试中验证。

### 3.2 Watch 平台层

- `HealthKitWorkoutPlatformSession`：只用于真实设备的 HealthKit 适配；
- `SimulatorWorkoutPlatformSession`：只用于 Simulator 的确定性流程数据；
- `ProductWorkoutViewModel`：把共享状态机映射到界面并每五秒请求检查点；
- `ProductWatchRootView`：开始页、基础数据页、杀球不可用页、控制页与结束摘要。

### 3.3 iPhone 正式端

当前只有明确的空历史首页，用于验证正式 target 与研发 target 隔离。运动同步、长期存储、报告和历史属于阶段 9–10，不能在阶段 4 文档中伪称完成。

## 4. 状态与失败规则

业务阶段为：

```text
idle
  → requesting_authorization
  → starting
  → running ⇄ paused
  → ending
  → completed
```

授权拒绝、平台会话错误、保存失败或本地检查点失败进入 `failed`，对应运动保留为 `interrupted`。错误必须对用户可见，不允许静默丢失或把中断运动标记为完成。

暂停区间不累计活动时长。开始、暂停、继续、结束及运动中每五秒保存检查点。应用重启时只认最后一次已经落盘的活动时长；关闭之后到重启之前的墙钟时间不计入运动。

## 5. 数据来源与展示规则

真实设备运动使用 `healthkit_device`。Simulator 使用 `simulator_synthetic`，结束后必须是 `simulated_not_saved`；数据校验器禁止把非真实设备运动标记为 HealthKit `saved`。

在真实动作数据门禁通过前：

- 总击球显示 `—`；
- 杀球数显示 `—`；
- 最近和最快杀球速度显示“暂无”；
- 不写入零值、随机值、固定公式值或模型占位字段；
- 正式运动 schema v1 不包含任何击球或速度字段。

心率与能量尚未产生时显示“等待”，不使用模拟默认值冒充健康数据。

## 6. 权限与降级

HealthKit 不可用、写入 workout 被拒绝或授权流程失败时，正式运动不得开始，并显示明确原因。Simulator 可进入流程测试，但界面持续提示“不写入健康”。

HealthKit 的读权限遵循系统隐私语义，应用不能从授权请求成功推断每一类健康数据都可读。因此心率或能量缺失必须保持为空，不得填充或报出虚假的正常值。

## 7. 当前恢复能力边界

已经实现：

- 正式运动事实增量落盘；
- 启动时识别未完成本地记录；
- 将其安全收口为中断记录；
- 即使隔天重启，也不会把关闭期间误算为活动时长。

尚未实现：

- WatchKit `handleActiveWorkoutRecovery`；
- `HKHealthStore.recoverActiveWorkoutSession`；
- 把恢复得到的平台 session 与对应本地运动 UUID 重新绑定。

因此当前恢复能力保护本地已落盘事实，但不能宣称应用被系统终止后仍能继续控制同一个 HealthKit 运动会话。该项必须在 S4-006 设计、实现并真机验证。
