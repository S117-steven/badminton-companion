# 研发数据导出格式

## 1. 状态与目的

- 格式版本：1
- 文件扩展名：`.badminton-ndjson`
- 适用范围：内部研发采集，不属于正式用户数据导出承诺

该格式用于让电脑端 Python、R 或其他逐行 JSON 工具直接读取完整采集，同时保持人工标签、测试者资料、原始样本和外部真实测速字段的可追溯关系。

## 2. 文件结构

文件使用 UTF-8 NDJSON，每行一个 JSON 对象。

第一行是 `ResearchCaptureExportHeader`：

- `recordType`：固定为 `badminton_research_capture_header`；
- `formatVersion`：当前为 `1`；
- `exportedAt`：导出时间；
- `manifest`：完整 `ResearchCaptureManifest`；
- `participant`：匹配到时为完整 `ResearchParticipant`，否则为 `null`。

从第二行开始，每行是一个原始 `ResearchMotionSample`，字段和数值不因曲线抽样或导出而修改。

## 3. 完整性与内存原则

- 导出通过流式复制原始 `samples.ndjson` 完成，不把整场高频数据一次性加载进内存；
- 目标文件已存在时拒绝覆盖，手机界面会先显式清理自己生成的同名临时导出；
- 先写临时文件，完成同步后再移动到最终路径；
- 导出结果返回样本数、测试者资料是否存在和文件字节数；
- 手机曲线最多均匀抽取 4,500 条记录仅用于显示，导出始终包含全部记录。

批量导出按日期、测试者、人工动作标签和复核状态筛选。每次采集仍生成一个独立 `.badminton-ndjson`，整个批次先写入临时目录，全部成功后再一次性发布目录。iPhone 使用系统文件选择器一次导出多个文件，不引入第三方压缩依赖。

## 4. 读取示例

伪代码：

```text
open file
header = decode first line
assert header.recordType == "badminton_research_capture_header"
assert supported(header.formatVersion)
for each remaining line:
    sample = decode ResearchMotionSample
    process sample by sample.source
```

分析脚本不得假设三类传感器天然同步。应按 `source` 和各自的单调时间戳分析或另行生成不覆盖原始数据的派生对齐结果。

## 5. 数据资格

脚本在纳入真实研究数据集前必须检查：

- `manifest.provenance == physical_sensor`；
- `manifest.reviewStatus == valid`；
- 采集模式和人工标签符合实验目的；
- 分来源质量摘要和原始间隔不存在不可接受异常；
- 如果使用外部真实速度，其状态和配对关系已经人工验证。

`simulator_synthetic` 与 `automated_test_fixture` 只能用于流程或脚本测试，不得进入真实算法训练、验证或产品准确率结论。
