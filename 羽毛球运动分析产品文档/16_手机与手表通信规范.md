# 手机与手表通信规范

## 1. 状态与边界

- 版本：0.3
- 日期：2026-08-14
- 当前实现范围：内部研发采集与算法无关的正式基础运动

研发采集使用清单和原始样本双文件。正式基础运动已经建立独立单文件协议；未来击球明细的数据包仍未锁定，必须在对应门禁后版本化。

## 2. 设计目标

- 手机不在线不影响手表采集和保存；
- 不依赖 `isReachable` 或即时消息；
- 每个采集以 UUID 去重；
- 部分文件到达不产生半条手机记录；
- 失败可以重试；
- 手机完整接收前不删除手表副本；
- 回执必须与 UUID 和 schema 匹配。

## 3. 传输方式

每次采集形成两个后台文件传输：

1. `manifest.json`；
2. `samples.ndjson`。

手表先为该次传输创建一份不可变文件快照，再使用 WatchConnectivity `transferFile` 入队。这避免清单同步状态的后续写入改变系统正在传输的字节。快照中的设备本地同步状态始终规范化为 `pending_transfer`，因此首次入队与回执丢失后的重试具有相同内容，不会被手机误判为 UUID 冲突。该接口由系统后台调度，不要求手机在采集或排队时实时可达。

每个文件的 property-list 元数据包含：

- `message_type = capture_file`；
- `capture_id`；
- `schema_version`；
- `file_kind`；
- `byte_count`。

## 4. 手表状态机

```text
local_only
    ↓ 采集结束或中断
pending_transfer
    ↓ 两个文件均交给系统队列
transferred
    ↓ 任一文件报告传输错误
pending_transfer

pending_transfer 或 transferred
    ↓ 收到 UUID 与 schema 匹配的手机回执
acknowledged
```

不允许从 `acknowledged` 回退或重复入队。`transferred` 表示已交给系统但尚未获得手机确认，应用重新激活时可再次入队，手机依靠 UUID 幂等去重。平台文件错误只把对应采集退回 `pending_transfer`，本地文件继续保留。

## 5. 手机入站

WatchConnectivity delegate 提供的临时文件只在回调期间可靠，因此手机先同步复制到应用自己的临时目录，再交给共享入站 actor。

入站规则：

- 单个文件到达时等待另一文件；
- 文件字节数必须匹配元数据；
- 清单 UUID 和 schema 必须匹配；
- NDJSON 实际记录数必须等于清单 `sampleCount`；
- 新采集通过临时目录整体移动进入长期目录；
- 相同 UUID 的采集事实与原始样本文件逐字节相同时视为幂等重复；
- 手机端后续修改的复核、备注和外部真实测速在重试时保留，不由手表重传覆盖；
- 相同 UUID 但内容不同拒绝覆盖；
- 任何失败都不发送回执。

## 6. 回执

手机完整导入或确认幂等重复后，使用后台 `transferUserInfo` 返回：

- `message_type = acknowledgement`；
- `capture_id`；
- `schema_version`。

手表读取本地清单并再次校验 schema。只有匹配才写入 `acknowledged`。

## 7. 用户复核与文件稳定性

手表采集结束后，采集者选择“有效、待检查或无效”中的一个状态。该次选择写入清单后，界面锁定本次手表复核并加入后台队列，避免排队期间继续修改同一清单文件。手机端仍可进行后续长期复核。

## 8. 当前测试者

手机保存当前测试者 UUID，并通过 WatchConnectivity `updateApplicationContext` 发布最新选择。手表收到后本地持久化，后续离线采集继续使用最后一次已同步的 UUID。真机上没有当前测试者时拒绝开始研发采集，避免生成无法与身高、臂展和水平资料对应的数据。

## 9. 当前验证限制

- 共享出站、入站、状态转换、元数据、当前测试者消息和回执已有自动测试；
- iOS 与 watchOS 平台适配器已编译；
- 已配对 Simulator 本次未交付文件，手表正确保持 `pending_transfer`；
- 苹果官方传输样例要求物理设备，因此最终结论必须来自真机；
- 尚未验证大文件耗时、应用终止、手机长期离线、部分文件、重复回执和系统重启。

## 10. 正式基础运动传输

正式运动当前以 `BadmintonWorkoutRecord` schema v1 的一个 `workout.json` 为原子事实包。只有 `completed` 和 `interrupted` 记录可传输，进行中的记录拒绝进入队列。

文件元数据：

- `message_type = workout_file`；
- `workout_id`；
- `schema_version`；
- `byte_count`。

手机完整导入或确认幂等重复后返回：

- `message_type = workout_acknowledgement`；
- `workout_id`；
- `schema_version`。

同步状态与运动事实分开保存：`pending_transfer → transferred → acknowledged`。文件错误可以从 `transferred` 回到 `pending_transfer`；未收到回执时允许再次排队；`acknowledged` 不回退。

## 11. 正式手机入站

手机在发送回执前验证：

- 字节数；
- UUID；
- schema；
- 运动已经结束或中断；
- 运动记录自身约束；
- 相同 UUID 是否为相同完整事实。

相同 UUID 和相同事实视为重复成功。相同 UUID 但事实不同视为冲突，拒绝覆盖且不发送回执。未来击球明细必须和单场统计形成新的原子版本包，不能让手机保存只有统计或只有部分击球的运动。

## 12. 正式传输验证限制

- 终态筛选、不可变快照、重试、回执、字节数、身份、schema、重复和冲突已有自动测试；
- iOS 与 watchOS 正式 WatchConnectivity 适配器已通过 Simulator SDK 编译；
- Simulator 不提供真实后台文件交付结论；
- 手机离线、应用终止、系统调度、回执丢失和多场连续运动仍必须真机验证。
