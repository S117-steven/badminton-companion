# 测试与验收基线

## 1. 当前任务边界

- 阶段：阶段 1 Simulator 收口，进入阶段 2；
- 输入：现有产品文档和研发阶段规范；
- 输出：Git、双端工程、共享核心、研发数据定义、测试者资料、采集会话、增量存储、异常恢复、入站完整性与去重、双端研发界面和测试；
- 不包含：真实传感器采集、HealthKit、WatchConnectivity 平台传输、算法和正式产品功能。

## 2. 自动测试层级

### 2.1 BadmintonCore 单元测试

当前覆盖：

- 自由打球不能带伪造逐拍人工标签；
- 批量采集的人工标签必须和模式一致；
- 原始样本追加写入后可无损读取；
- 人工标签不会在持久化过程中变化；
- 采集完成后进入待传输状态；
- 外部真实速度默认保持为空；
- 重复 UUID 不覆盖已有采集。
- 测试者资料校验、版本化分级和本地往返；
- 采集来源与数据源来源不一致时拒绝启动；
- 采集数据按批追加并生成实际间隔摘要；
- 运动数据源失败后形成可恢复的中断采集；
- 应用启动恢复遗留 `collecting` 清单；
- 采集 UUID 冲突不会结束或改写既有采集；
- 双文件入站等待、字节数校验、样本数校验与幂等导入。

### 2.2 工程构建

必须分别构建：

- `BadmintonResearchiOS`；
- `BadmintonResearchWatch`。

共享包成功构建不等于双端应用成功构建。

## 3. 当前验证结果

2026-08-12 阶段 1 Simulator 回归：

- Swift Package 单元测试：13 个通过，0 个失败；
- iOS 27 模拟器 SDK Debug 构建：通过；
- watchOS 27 模拟器 SDK Debug 构建：通过；
- iPhone 17 Simulator 安装与启动：通过；
- Apple Watch SE 3（40 mm）Simulator 安装与启动：通过；
- iPhone 测试者资料创建并保存：通过（175 cm、177 cm、`research_v1_regular`）；
- iPhone 双文件入站与列表展示：通过（30 条 `simulator_synthetic` 样本）；
- Apple Watch 采集开始、实时计数、停止、落盘和有效性标记：通过（5,436 条 `simulator_synthetic` 记录）；
- 两端落盘清单的来源、完成状态、样本数和复核状态只读核对：通过；
- 真机安装与运行：未验证；
- 真实传感器采样：未实现、未验证；
- 手机离线的本地保存逻辑：Simulator 与自动测试通过，真机未验证；
- WatchConnectivity 实际传输：未实现、未验证。

Simulator 合成记录同时生成加速度计、陀螺仪和设备运动三类记录，因此“样本数”是记录条数，不等于某一单独传感器的采样帧数。该结果只验证采集链路吞吐与持久化，不代表真实 Apple Watch 的频率、同步性或数据质量。

## 4. 阶段 0 完成判定

Simulator 范围已满足：

- 文档入口清楚；
- iPhone 和 Watch targets 已建立，能够构建、安装和启动；
- 共享模块和基础自动测试已建立；
- 没有伪算法。

仍需在后续真机阶段补验：

- 配置真实 Bundle Identifier 和开发团队；
- iPhone 最小应用安装运行；
- Apple Watch 最小应用安装运行；
- 双端显示内部研发入口。

因此阶段 0 的 Simulator 工程基线已经关闭并可进入阶段 1；项目总规范要求的真机完成条件仍明确保留，不能用本结论替代。

## 5. 阶段 1 Simulator 完成判定

Simulator 范围已满足：

- 单次、普通批量、杀球批量、自由和干扰采集入口可达；
- 人工标签不会被模型输出覆盖；
- 测试者资料具有稳定 UUID 和版本化分级；
- 可注入数据源能够驱动准备、采集中、停止、完成和失败状态；
- 高频记录分批落盘，异常遗留采集可恢复为 `interrupted`；
- 手机入站完整性、样本数、重复与冲突规则已建立；
- Simulator 和自动测试数据不能冒充真机研究数据；
- 未实现任何击球检测或测速占位算法。

仍需真机或平台适配器补验：Core Motion、长时间/离线运行、WatchConnectivity 实际发送与确认。故本结论只关闭阶段 1 的 Simulator 实现范围，不解除阶段 2 真机门禁。

## 6. 后续阶段禁止替代的真机测试

以下不能用模拟器结果代替：

- Core Motion 实际采样频率和时间戳稳定性；
- 高速挥拍峰值与传感器饱和；
- 长时间采集、电量、发热和内存；
- 后台与异常中断恢复；
- WatchConnectivity 断线、重试和去重；
- HealthKit 心率、热量和运动记录；
- 震动反馈；
- 设备端实时推理性能。

## 7. 回归要求

每次修改共享数据结构或存储格式时：

- 更新 schema 版本或提供向后兼容读取；
- 保留人工标签和外部真实测速的独立性测试；
- 运行 BadmintonCore 全部测试；
- 构建 iOS 和 watchOS；
- 更新数据定义与已知问题。
