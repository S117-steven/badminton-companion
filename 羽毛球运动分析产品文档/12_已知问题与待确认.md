# 已知问题与待确认

## 1. 产品决策待确认

1. 身高、臂展、羽毛球水平哪些为正式产品必填，哪些可选。
2. 羽毛球水平最终分级。PRD 给出“初学、普通、进阶、竞技”，总规范仍把具体分级列为待确认。
3. 原始数据长期保存整场还是只保存事件窗口，以及保存期限。
4. 无成功测速杀球时的最终文案。
5. 平均杀球速度的最少有效样本数。
6. 最终界面视觉风格。

这些问题当前不阻塞内部采集基础，但不得在正式产品代码中写死。

## 2. 工程配置待确认

1. 正式 Bundle Identifier 与内部研发 Bundle Identifier。
2. Apple Developer Team、签名和设备注册。
3. 最低 iOS 与 watchOS 版本。
4. 是否需要单独的研究数据导出 macOS 工具。

当前 iOS 17、watchOS 10 和 `com.example` 标识仅为集中可替换的工程基线。

## 3. 阶段 1 至阶段 2 技术待确认

1. Core Motion 各接口在目标 Apple Watch 上的实际频率和稳定性。适配器代码已实现，仍无真机结论。
2. 加速度计、陀螺仪、设备运动是否同时采集，以及资源开销。
3. 分批落盘大小与检查点间隔。当前 Simulator 基线为协调器可配置，手表使用 75 条记录一批；真机需按写入、电量与恢复损失实测调整。
4. 长时间运行所需的运动会话和权限方案。
5. 疑似丢样、异常间隔和传感器饱和的研究阈值。
6. 原始 NDJSON 在真实采集量下的性能；如需替换格式，必须保留可导出、可追溯和可恢复能力。
7. 手表数据传输批次、确认和重试的真机参数。当前采用清单与样本双文件、后台文件传输、手机完整导入后后台回执；具体大文件耗时、失败行为和系统调度仍待真机验证。

## 4. 当前已知限制

- Apple Watch Simulator 可以创建显式合成采集；真机 Core Motion 代码已接入，但尚未在目标设备运行；
- iPhone 可以管理测试者、接收 WatchConnectivity 双文件、显示采集列表、曲线和导出；WatchConnectivity 尚未真机验证；
- 当前测试者选择、多文件导出和真实测速表单已编译，但真机 application context 和系统文件选择器仍待交互验收；
- 只验证了模拟器 SDK 构建，没有安装到真机；
- 当前没有应用图标和最终视觉资产；
- 当前没有健康权限或正式运动会话；WatchConnectivity 代码已实现但尚无真机交付结论；
- 当前没有任何核心算法。

## 5. 技术债

当前没有用临时模型或模拟数据形成算法技术债。Simulator 数据通过 schema v2 的 `provenance` 强制标记并在界面警示，不具备真实研究资格。

NDJSON 是早期可审查格式，可能在大规模采集后需要升级；该风险已通过 schema 版本、每次采集独立目录和存储接口隔离。升级时不得静默改写已经采集的原始数据。

当前 `ExternalSpeedReference` 与整次采集一对一，因此不支持在一个杀球批量段内录入多个逐拍真实速度。该限制优先避免错配，真实测速实验需要逐拍时再以新 schema 增加独立配对记录。
