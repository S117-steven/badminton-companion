# 数据定义初稿

## 1. 文档状态

- 数据结构版本：3
- 日期：2026-08-12
- 范围：内部研发采集 schema v3 与正式基础运动 schema v1
- 对应实现：`Packages/BadmintonCore`

本文件定义当前研发数据和阶段 4 正式基础运动。正式击球记录和算法输出仍需在对应研究门禁通过后另行版本化。

## 2. 基本原则

- 原始样本、人工标签和未来模型输出必须是不同字段；
- 人工标签不得被模型覆盖；
- 外部真实速度与估算速度必须是不同数据对象；
- 高频原始样本不嵌入单个大型清单 JSON；
- 每次采集和每位测试者使用 UUID；
- 字段含义和单位通过 schema 版本追溯；
- 原始设备坐标不得被左右手标准化结果覆盖。
- 每次采集必须标记数据来源；Simulator、自动测试与真机数据不得混淆。

## 3. 研发采集模式

| 代码 | 含义 | 标签规则 |
|---|---|---|
| `single_action` | 单次动作 | 开始前必须人工选择标签 |
| `normal_shot_batch` | 普通击球批量 | 固定人工标签 `normal_shot` |
| `smash_batch` | 杀球批量 | 固定人工标签 `smash` |
| `free_play` | 自由连续打球 | 不允许伪造逐拍人工标签 |
| `interference` | 干扰动作 | 必须人工选择干扰标签 |

当前人工标签包括普通击球、杀球、空挥、跑动、捡球、甩手、擦汗和其他干扰。它们用于内部研发，不代表正式用户侧会出现更多击球类型。

## 4. 测试者数据

`ResearchParticipant`：

- `id`：测试者 UUID；
- `heightCentimeters`：身高，厘米；
- `armSpanCentimeters`：臂展，厘米；
- `skillLevelCode`：带版本语义的研究分级代码。
- `skillLevelDefinitionVersion`：研究分级定义版本；
- `createdAt`、`updatedAt`：资料创建与更新时间。

由于正式羽毛球水平分级仍有文档待统一，核心层暂不把四个中文选项写死为不可扩展枚举。手机研发界面加入资料编辑时，需要同时记录分级定义版本。

## 5. 设备元数据

每次采集保存：

- 硬件型号；
- 操作系统版本；
- 应用版本；
- 应用构建号。

后续真机接入还应补充佩戴方向、表冠方向以及平台能够可靠提供的设备标识信息，但不得采集不必要的个人设备身份数据。

## 6. 数据来源

`ResearchDataProvenance`：

- `physical_sensor`：真实设备传感器数据，可在人工复核与实验条件满足后进入研究数据集；
- `simulator_synthetic`：Simulator 确定性合成数据，只用于流程验收；
- `automated_test_fixture`：自动测试夹具数据，只用于测试。

只有 `physical_sensor` 具备进入真实研究数据集的来源资格。采集清单声明的来源必须与实际运动数据源一致，否则采集会话拒绝启动。

## 7. 原始运动样本

`ResearchMotionSample` 每条包含：

- `sequenceNumber`：同一数据流内递增序号；
- `source`：加速度计、陀螺仪或设备运动；
- `monotonicTimestampSeconds`：平台单调时钟时间戳，秒；
- `elapsedTimeSeconds`：相对本次采集开始的时间，秒；
- `actualIntervalSeconds`：与同源上一样本的实际间隔，首条可为空；
- `accelerationMetersPerSecondSquared`：三轴加速度，米/秒²；
- `angularVelocityRadiansPerSecond`：三轴角速度，弧度/秒；
- `gravity`：平台提供的无量纲重力方向向量；
- `userAccelerationMetersPerSecondSquared`：去重力用户加速度，米/秒²；
- `attitudeQuaternion`：姿态四元数。

不同传感器回调不要求伪同步。某条记录只填写其真实来源能够提供的通道，其余通道为空。未来如生成对齐或标准化序列，必须作为派生数据另存，不能覆盖原始记录。

## 8. 采集清单

`ResearchCaptureManifest` 主要字段：

- schema 版本；
- 采集 UUID；
- 测试者 UUID；
- 采集模式；
- 人工标签；
- 数据来源；
- 开始和结束时间；
- 采集状态；
- 有效性复核状态、无效原因和备注；
- 设备元数据；
- 已落盘样本数；
- 采样质量摘要；
- 可选外部真实测速引用；
- 同步状态。

采集状态：`collecting`、`completed`、`interrupted`。

复核状态：`pending`、`valid`、`invalid`。

同步状态：`local_only`、`pending_transfer`、`transferred`、`acknowledged`。

## 9. 采样质量摘要

当前预留：

- 请求采样间隔；
- 实际平均间隔；
- 最大间隔；
- 异常间隔数量；
- 疑似丢样数量；
- 疑似传感器饱和样本数量。

schema v3 增加 `sourceSummaries`，按加速度计、陀螺仪和设备运动分别保存：

- 该来源记录数；
- 请求间隔；
- 实际平均间隔；
- 实际最大间隔；
- 异常间隔、疑似丢样和疑似饱和计数。

清单顶层的间隔字段保留为跨来源汇总，用于兼容和快速查看；研究结论应优先使用分来源摘要。v2 清单读取时 `sourceSummaries` 为空，不应伪造分来源结果。

异常间隔和饱和判定阈值尚未确定。判定结果只是质量元数据，不得用来删除或修改原始样本。

## 10. 外部真实测速

`ExternalSpeedReference` 包含：

- 原始测量值；
- 原始单位 `km/h` 或 `m/s`；
- 测速设备或方法描述；
- 待复核、已验证或已拒绝状态；
- 样本配对标识。

该对象默认为空。未来任何模型估算值都不得写入此对象。

当前清单只能表达一个外部速度，因此仅“`physical_sensor` + 单次动作 + 人工标签杀球”允许录入。Simulator 和自动测试数据不得写入外部真实速度。批量杀球段不能用一个模糊的速度代表多次击球；如后续需要逐拍外部配对，必须新增独立配对数据结构并升级 schema。测量值必须为大于零的有限数，测速来源和配对标识不得留空。

## 11. 当前文件布局

```text
ResearchData/
├── Captures/
│   └── <capture-uuid>/
│       ├── manifest.json
│       └── samples.ndjson
├── Participants/
│   └── <participant-uuid>.json
└── Inbox/
    └── <capture-uuid>/
        ├── manifest.json
        └── samples.ndjson
```

`manifest.json` 使用原子替换更新；`samples.ndjson` 每行一个完整 JSON 样本并追加写入。该格式便于早期审查和脚本读取，但大规模真机数据积累前必须评估体积、写入开销和导出效率。

入站目录只有在两个文件完整到达并通过校验后才原子导入 `Captures`。导入成功后清理对应入站目录。

研发导出为 `.badminton-ndjson` 单文件：首行为版本化 header，包含清单和可选测试者资料；后续每行是未改写的 `ResearchMotionSample`。详见 `15_研发数据导出格式.md`。

## 12. 校验规则

- 自由打球不允许预填逐拍人工标签；
- 需要人工标签的模式不得留空；
- 普通和杀球批量模式的标签必须与模式一致；
- 结束时间不得早于开始时间；
- 样本数不得为负；
- 已存在采集 UUID 不得覆盖；
- 已结束采集不得继续追加样本；
- 入站文件声明字节数必须与实际一致；
- 清单 UUID 与 schema 必须匹配传输元数据；
- 清单样本数必须与 NDJSON 实际记录数一致；
- 相同 UUID 的采集事实与原始样本文件逐字节相同时视为幂等重复；仅样本数相同不足以判定重复；
- 手机导入后可修改复核状态、无效原因、备注和外部测速，重传只校验原始采集事实并保留这些手机端研发元数据；
- 采集清单来源必须与实际数据源来源一致。

## 13. 正式基础运动记录

`BadmintonWorkoutRecord` 的 schema v1 是算法无关的运动事实。当前字段：

- `id`：每场运动 UUID；
- `provenance`：`healthkit_device`、`simulator_synthetic` 或 `automated_test_fixture`；
- `startedAt`、`endedAt`、`updatedAt`、`lastMetricAt`；
- `lifecycleState`：启动中、运动中、暂停、已完成或已中断；
- `accumulatedActiveDurationSeconds`与 `lastResumedAt`；
- 健康授权状态与健康写入状态；
- 可选 HealthKit workout UUID；
- 当前、平均和最高心率（次/分）；
- 活动与总能量（千卡）；
- 可选失败代码与说明。

暂停时间不进入活动时长。正在运动时定期将已证实活动时长写入检查点；异常恢复时不把应用关闭后的墙钟时间计入运动。

Simulator 运动必须使用 `simulator_synthetic + simulated_not_saved`，校验器禁止将其标记为 HealthKit 已保存。

schema v1 故意没有总击球、杀球和速度字段。在真实数据门禁通过前，界面使用“—/暂无”而不是伪造零值。

## 14. 正式基础运动文件布局

```text
ProductData/
└── Workouts/
    └── <workout-uuid>/
        └── workout.json
```

`workout.json` 每次使用原子替换。当前仅是手表本地事实库；运动及未来击球明细的手机长期同步结构属于阶段 9。
