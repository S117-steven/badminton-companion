# 文档索引与优先级

## 1. 目的

本目录用于统一约束苹果手表与苹果手机双端羽毛球运动分析应用的产品研发。

任何编码代理、设计人员或开发人员在开始任务前，都应先阅读与当前任务有关的文档。不得仅根据已有代码、界面截图或单次指令自行推断产品需求。

## 2. 当前开发阶段

当前项目正式增加一个位于正式产品之前的“内部数据采集阶段”。

开发顺序为：

1. 先完成内部数据采集测试版；
2. 由产品负责人本人在真实打球过程中持续采集数据；
3. 验证苹果手表高速运动数据质量；
4. 研究真实击球检测；
5. 研究杀球与普通击球区分；
6. 获取少量真实测速基准；
7. 研究杀球速度估算；
8. 核心算法通过验证后，再集成到正式产品。

正式产品的界面与基础架构可以并行设计，但在相应技术门禁通过前，不允许用占位算法生成正式杀球分类或杀球速度。

## 5. 正式第一版核心边界

正式第一版只聚焦羽毛球。

核心能力：

- 苹果手表独立记录羽毛球运动
- 基础运动健康记录
- 自动确认真实击球
- 用户侧只区分杀球与普通击球
- 总击球数和杀球数
- 对满足条件的杀球估算速度
- 杀球识别后的轻微震动
- 可选个人动作校准
- 运动结束后同步到苹果手机
- 手机端单场报告、击球明细、历史运动和个人纪录
- 写入苹果健康与健身体系

正式第一版明确不做：

- 网球
- 比分
- 回合识别
- 具体球路细分
- 普通击球测速
- 挥拍强度评分
- 击球质量评分
- 疲劳分析
- 训练建议
- 球拍管理
- 摄像头分析
- 云端账号
- 社交和排行榜
- 自动重算历史结果

## 6. 内部数据采集测试版边界

内部数据采集测试版属于研发工具，不属于正式用户功能。

它的目的：

- 获得真实苹果手表高速运动数据
- 建立人工已知标签的普通击球和杀球数据
- 收集空挥与其他干扰动作
- 验证连续采样稳定性
- 为后续真实击球检测、杀球识别和杀球测速提供数据

研发工具允许具有正式产品不提供的能力：

- 单次击球采集
- 普通击球批量采集
- 杀球批量采集
- 自由连续采集
- 空挥和干扰动作采集
- 原始传感器曲线查看
- 样本有效性标记
- 研发数据导出
- 外部真实测速值录入
- 采样质量和疑似传感器饱和检查

研究入口不得出现在正式发布版本中。

## 7. 编码代理不得自行决定

编码代理不得自行：

- 扩大第一版功能范围
- 用简单阈值直接代替正式杀球模型
- 用固定系数直接代替正式杀球测速
- 生成随机或伪造速度
- 用模型自己的预测自动覆盖人工标签
- 将无真实测速依据的数值写入“真实速度”字段
- 增加球拍参数要求
- 增加云端账号或服务器
- 修改个人动作校准的十加十规则
- 改变手机和手表职责
- 让手机成为运动过程必需设备

包括：

- 实际采样频率和采集接口

- 数据导出文件结构

- 真实击球检测算法
- 杀球识别模型
- 个人动作校准如何参与模型
- 杀球速度估算模型
- 各类可信度阈值
- 原始数据保留期限
- 最低系统版本
- 电量目标
- 最终视觉风格

## 9. 当前工程状态

截至 2026-08-12：

- Git 仓库已经建立，主分支为 `main`；
- iPhone 与 Apple Watch 内部研发版 target 已建立；
- 双端共享 `BadmintonCore` 本地 Swift Package 已建立；
- 研发采集清单、人工标签、来源标记、传感器样本和追加式本地文件存储已建立；
- 测试者资料、采集会话状态机、分批落盘、异常恢复和手机双文件入站校验已实现；
- 手表与手机 Simulator 研发流程均已实际运行，合成数据不会被标记为真机数据；
- iOS 与 watchOS 模拟器构建已通过；
- Core Motion 真机适配器已实现并通过模拟器 SDK 编译，但尚无任何真机数据质量结论；
- 手机原始曲线和完整 NDJSON 导出已实现；WatchConnectivity 双文件、回执和重试代码已实现，真机待验；
- 当前没有实现任何击球检测、杀球分类或杀球测速算法。

当前阶段表述为：阶段 1 的 Simulator 范围已关闭，阶段 2 代码基线已建立；阶段 0 至阶段 2 中所有真机验收仍待签名、真实设备和真实打球数据验证，阶段 2 门禁尚未通过。
